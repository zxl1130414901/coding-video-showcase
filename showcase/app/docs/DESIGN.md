# 设计说明（DESIGN）

## 1. 信息架构

```text
应用
├─ 顶部栏：品牌 / 主导航（选型首页 · 全部项目 · 总览 · 时间线）/ 数据来源与项目数
├─ 主内容
│  ├─ 选型首页（#/，默认）：一句话定位 + 大搜索框 → 「你想做什么」10 张场景卡 → 「先按条件筛」11 个约束 chip → 结果区 → 「我现在就要一条片」8 条 quickPick → 对比入口
│  ├─ 场景页（#/scenario/<id>）：首选大卡（视频 / 理由 / 上手时间 / 六维评分 / 能力标签 / 详情入口）→ 备选对比列表 → 该场景全部符合条件的仓库
│  ├─ 全部项目（#/all）：筛选面板 → 图例 → 15 列可排序表格 → 底部对比栏（进阶视图）
│  ├─ 总览：4 张指标卡 → 分布环图（分类 / Star 区间）→ 分类快捷入口
│  ├─ 时间线：活跃度柱状图 → 四档图例 → 最近更新 Top 10
│  └─ 详情页（全页）：#/repo/<id> → 8 个信息分区
├─ 对比弹窗（2–3 项并排：基础指标 + 13 行档案级差异）
└─ 全局 Toast（复制成功、选择上限提示）
```

### 1.1 为什么这样排（v4）

旧版默认落在 65 行矩阵，要求使用者先读懂 15 列字段再自行取舍——「从使用者角度，他怎么能快速找到自己想要的呢？」这个问题没有被回答。v4 把入口改成**按需求选型**，矩阵降级为进阶视图：

1. **需求优先于参数**：普通使用者先想到的是「我要做数学动画 / 我要一条竖屏短片」，不是「GPU 支持是 required 还是 none」。首页因此把 10 个真实问题（`questionZh`）放在第一屏，`titleZh` 只作为分类标签。
2. **每个场景只给一个默认答案**：场景卡直接展示首选仓库的缩略图、名字与一句 `whyZh`，点进去就是可播放的首选大卡；备选区回答「为什么不是首选、什么时候选它」。避免 10 个平铺选项重新制造选择困难。
3. **硬条件用 AND 叠加**：11 个约束 chip 是使用者真实的排除条件（无 GPU、Windows 可用、5 分钟装完、有 CLI……）。多选即 AND，结果区实时播报「满足全部 N 条 · 剩余 M 个」，并逐条标出命中的约束，让筛选过程可解释。
4. **搜索接受口语**：`discovery.json` 的 `synonyms` 把「数学动画」「终端录制」「React 视频」等说法映射到仓库与能力词；搜索按「原词 + 同义词 + 仓库名片段」展开，并在结果上方给出最接近的场景入口。零结果时给 3 个可点推荐词，而不是空白。
5. **两条出口**：想快速出片走 quickPick（8 条「需求 + 仓库 + 上手时间」横向卡）；拿不定就进 `#/all` 勾选 2–3 个并排对比。矩阵、总览、时间线一个都没删，只是不再挡在第一步。
6. **首屏轻**：首页只渲染缩略图（`loading="lazy"`），视频仅在详情页与场景首选大卡挂载，首屏不加载 51 个 `<video>`。

## 2. 核心交互流

### 2.1 从概览到矩阵

1. 概览读取 `computeOverviewStats`，四张卡展示总数 / 出片 / 未出片 / 体积。
2. 点击分布环图的「分类分布 ↔ Star 区间」切换统计维度，不跳页。
3. 点击分类 chip → 写入筛选条件并切到矩阵视图（`onApplyCategory`）。

### 2.2 矩阵筛选与排序

1. 关键词输入对仓库名、`descriptionZh`、标签做不区分大小写匹配。
2. 分类、样例状态、Windows、GPU 使用 chip / 分段控件；许可证、语言收进「更多筛选」。
3. 每次变更同步更新 `n / 总数` 计数；「重置」恢复空筛选。
4. 点击任意表头切换升序 / 降序；空值始终排在最后；`aria-sort` 同步。
5. 行可点击（Enter / Space）打开详情；左侧复选框用于对比选择。

### 2.3 独立详情页（`#/repo/<id>`）

1. 入口：矩阵行（Enter / Space）、时间线 Top 10、对比弹窗表头、compareTips / 替代项目、直接深链。打开后 `view=detail`，并记录 `fromView` 以便返回。
2. Hero：仓库名 + tagline + GitHub / 主页 / 本地目录 + Star / 许可 / 语言 / 最近推送 + 分类、样例、档案、能力分段四个徽章；右侧为缩略图与六维评分。
3. 信息分区按固定顺序：能做什么 → 适用场景 → 能力上限 → 完整工作流 → 差异化与硬短板 → 和谁比怎么选 → 样例 → 实测证据。每区有编号、说明与 `aria-labelledby`。
4. 能力上限：4 个统计卡（分辨率 / 帧率 / 时长 / 导出格式）+ 7 行字段表；`ceilingZh` 按句重排为每段 ≤3 句、行宽 ≤72ch 的正文。
5. 档案缺失：`buildFallbackDetail` 用 `repos.json` 合成回退档案，顶部黄色「档案未就绪」+ 说明，所有分区仍有内容，禁止白屏。
6. 样例：默认 `sample.mp4` 能力演示，可切 `sample_basic.mp4`；有 `features.json` 时显示分段条、点击定位、callout 时间轴与已知限制；缺失时显示明确降级提示。规格区优先显示能力演示实测时长 / 体积（构建期 stat 注入），帧数为推算值。
7. 离开：返回按钮回到 `fromView`（默认矩阵），筛选条件与对比选择保持不变；页面 `<title>` 随仓库变化，进入时焦点落在 H1。

### 2.4 对比模式

1. 列表、时间线与详情页均可加入对比（最多 3 项），底部对比栏实时显示 `n/3`。
2. 「开始对比」打开弹窗：先按基础指标逐维度标优 / 标差，再追加 13 行「深度档案差异」——核心定位、分辨率 / 帧率 / 时长上限、导出格式、适用场景、工作流、自动化、实时预览、CI、硬短板、差异化、能力分段。
3. 档案缺失的项目回落到基础字段，并在格内显示「档案未就绪」，不输出 undefined / 空单元格。
4. 「复制 Markdown」生成结构化结论并写入剪贴板，Toast 反馈；选择少于 2 项时弹窗自动关闭。

### 2.5 深链与刷新还原

- 路由使用 hash，四个主路由：`#/`（选型首页，默认）、`#/scenario/<id>`（场景页）、`#/all`（全部项目矩阵）、`#/repo/<id>`（详情页）。
- 兼容旧深链：`#/?view=matrix&category=...` 落到矩阵，`#/?view=overview|timeline` 保留；带筛选条件但未指定视图时默认进入矩阵。
- 排序 / 对比选择 / `from` 来源视图 / 详情页的来源场景（`scenario`）都会序列化；返回按钮按 `fromView` 回到场景页或全部项目。
- 启动时 `parseRouteHash` 解析；路由变化时 `syncLocationHash` 回写；`hashchange` 监听浏览器前进/后退。
- `#/repo/<id>` 始终以详情页为准，即使同时带 `view` 参数；未知场景 id 显示中文错误态并提供回首页按钮，不白屏。

### 3.3 排版

| 层级 | 字号 / 行高    | 用途                      |
| ---- | -------------- | ------------------------- |
| 标题 | 28–44px / 1.15 | 视图 H1、抽屉标题         |

| 辅助 | 12–13px / 1.5  | eyebrow、单位、时间、脚注 |

数值、时间、评分统一使用 `--font-mono`（Cascadia Mono / Consolas / ui-monospace），便于纵向对齐比较。

## 4. 布局与响应式

- 内容容器 `min(1600px, 100%)`，水平内边距 32px；详情页内容宽度收敛到 1180px，正文 ≤72ch。
- 四档断点：1280 / 1024 / 768 / 480，对应验收视口 1440 / 1024 / 768 / 375。
- 概览指标卡：4 列 → 2 列 → 1 列；分布图由左右布局转为上下堆叠。
- 矩阵保持横向滚动并让表头与首列在滚动时可用；窄屏隐藏次要列，保留仓库、Star、分类、样例状态、综合分。
- 详情页：Hero 两栏（1fr + 330px）→ 1150px 起压缩侧栏 → 900px 单栏；能做什么 3 → 2 → 1 列；能力上限两栏 → 单栏；统计卡 4 → 2 → 1 列；工作流与证据表在窄屏纵向堆叠。
- 375px 顶部导航压缩按钮内边距并隐藏项目数，四项导航仍完整可用，无横向溢出。
- 对比弹窗在窄屏改为纵向卡片堆叠，避免横向挤压。

## 5. 无障碍

- 语义：`header/nav/main/footer`、`table` + `th[scope]`、`aria-sort`、`aria-pressed`、`aria-current`；详情页每个分区用 `section[aria-labelledby]`，标题为真实 `h2`。
- 键盘：所有交互元素可 Tab 到达；表格行 Enter / Space 打开详情；对比弹窗实现 Tab 焦点循环与 Esc 关闭；详情页进入时聚焦 H1（`tabIndex=-1`）。
- 焦点：全局 `:focus-visible` 使用 2px 青蓝 focus ring；详情返回按钮先于内容出现，`scrollTo(0,0)` 后聚焦标题，避免读屏从页面中部开始。
- 读屏：对比弹窗 `role="dialog"` + `aria-modal` + `aria-labelledby`；视频有 `aria-label`（含仓库名与「能力演示 / 基础样例」）；`<details>` 证据区使用原生 summary；纯装饰图标 `aria-hidden`；提供「跳到主要内容」skip link。
- 对比度：正文 `--text-secondary` 与 `--muted` 在 `#0c141d` / `#060a0f` 上均 ≥4.5:1；强调色只用于链接与状态，状态同时有文字标签。
- 动效：视图淡入 180ms、抽屉已移除、弹窗 180ms；`prefers-reduced-motion: reduce` 下全部压缩到 0.01ms。
- 对比结论不仅靠颜色，同时输出「更优 / 更差」文字标签，色觉障碍用户同样可读。
- 空态、加载态、错误态、档案缺失态均有独立文案与图标，不依赖颜色传达含义。

## 6. 视觉原则

- 深色单一强调色，信息密度优先；不引入渐变遮罩、玻璃拟态等装饰。
- 1px 描边区分层级，圆角克制在 4–6px。
- 表格数值列右对齐 / 等宽，布尔与状态列用文字标签而非仅图标。
- 动效只服务于「新内容进入」与「层级切换」，不做持续动画；骨架屏脉冲在减少动效模式下关闭。

## 7. 详情页规范（v2）

### 7.1 分区与数据来源

| 分区       | 数据源                                  | 呈现规则                                                         |
| ---------- | --------------------------------------- | ---------------------------------------------------------------- |
| Hero       | `repos` + `details.taglineZh/summaryZh` | 四徽章 + 元信息 + 双入口按钮 + 右侧评分；档案缺失显示黄色提示    |
| 能做什么   | `whatItMakes[]`                         | 3 → 2 → 1 列卡片，强度标签；无档案时合成 1 张「基础定位」卡片    |
| 适用场景   | `useCases[]`                            | 场景 / 人群 / 为什么 / 交付物 / 契合度，2 列卡片                 |
| 能力上限   | `capabilities` + `ceilingZh`            | 4 统计卡 + 7 字段表 + 长文按 ≤3 句分段，行宽 ≤72ch               |
| 工作流     | `workflow[]`                            | 纵向步骤条，序号等宽，每步标注投入成本；空档案给出占位文案       |
| 差异化短板 | `differentiators[]` / `limits[]`        | 双栏，短板不折叠、不隐藏，红色顶边 + 红点列表                    |
| 和谁比     | `compareTips[]` + `alternatives[]`      | `vs` 解析为仓库后是可点击按钮，跳转对应详情；无目标显示虚线 chip |
| 样例       | `sample` + `features.json` + `showcase` | 能力演示 / 基础样例切换；分段条 + callout 时间轴 + 规格表        |
| 实测证据   | `evidence[]`                            | 原生 `<details>` 折叠，字段 / 来源文件 / 说明三列                |

### 7.2 硬性约束

- **禁止空区块**：任何分区 `innerText` 长度 > 40，且全页不出现 `undefined` / `NaN` / `[object Object]`。
- **档案缺失不白屏**：`resolveDetail` 返回 `buildFallbackDetail`，并在 Hero 与页面顶部双重标注「档案未就绪」。
- **features 缺失只降级不报错**：视频、规格照常可用，分段区显示「尚未生成能力分段档案」。
- **样例规格诚实**：能力演示模式优先用 `features.durationSec` / 视频元数据 / 构建期 stat 体积；帧数标注「推算」，基础样例沿用 `repos.json` 实测规格。
- **可分享**：`#/repo/<id>`、`from`、筛选、排序、对比选择全部可还原；`<title>` = `<owner>/<repo> · 代码转视频横评`。
- **返回上下文**：筛选状态与对比选择不因进入详情而重置。

### 7.3 数据装载

- 构建期 `virtual:repos` 同时注入 `reposPayload` / `detailsPayload` / `featuresPayload` / `sampleSizesPayload`。
- 真实数据模式启动前校验：`repos.length ≥ 51`，否则构建失败并输出中文错误；运行时二次校验字段完整性。
- `details/*.json` 与 `_samples/<id>/features.json` 均为**可选**输入；解析失败只警告并跳过对应仓库。
- 样例视频只被 `stat` 读取体积与路径引用，不复制、不写锁文件，可与其他任务并行替换。

## 8. 选型入口实现约定（v4）

### 8.1 数据与纯函数

- `showcase/data/discovery.json` 只读注入为 `virtual:repos` 的 `discoveryPayload`（`scenarios / constraints / quickPicks / synonyms / warnings`），前端不改写。
- `src/lib/discovery.ts` 承载全部选型判断：约束字段口径（`windowsTier / needsGpu / installComplexity / pipeline / hasCli / batchable`，与 `validate-discovery.mjs` 一致）、AND 叠加筛选、同义词扩展搜索、场景推荐、场景符合清单。
- 排序权重：仓库 id 精确命中 > 仓库名片段 > 标签 / 技术栈 / tagline / useCases 文本命中；同义词列表靠前的目标获得小幅优先级加分，保证「数学动画」把 manim 排在第一。

### 8.2 交互与可达性

- 场景卡与约束 chip 均为真实 `<button>`；约束 chip 带 `aria-pressed`，再次点击即取消。
- 搜索框支持 `/` 聚焦、`Esc` 清空；结果区 `aria-live="polite"` 播报数量变化；零结果给 3 个可点推荐词。
- 搜索、约束的实时计数与结果都带有解释标签（命中的约束、命中词），不做无反馈的静默过滤。
- 首页视频零挂载：场景卡与列表只用懒加载缩略图；场景首选大卡才挂载 `<video>`。

### 8.3 响应式

- 场景卡：1440 / 1024 为 4 / 3 / 2 列，768 起单列；quickPick 与约束 chip 在 768 以下横向滚动，页面本身不横向溢出。
- 搜索框在 768 以下改为上下布局，输入框高度 50px、字号 15–16px，避免移动端聚焦缩放。

## 9. 口语长句检索（v5）

### 9.1 意图语料（构建期一次性产出，运行时零模型）

- 新增 `showcase/data/intents.json`，由「仓库档案 + 场景契约」派生：`repos`（65 个仓库 × 14 条 = 910 条）、`scenarios`（10 个场景 × 10 条 = 100 条）、`global`（15 条通用说法）。
- 每条 `q` 12–25 字、第一人称口语，必须能在该仓库 `details` 的 `useCases / whatItMakes / ceilingZh` 中找到依据；覆盖能力型（「想让公式一步一步推出来」）、场景型（「做产品发布会开场动画」）、约束型（「要能批量跑 200 条」）。
- 同一仓库内不写同义重复，跨仓库不写近似句；`scenario` 只能取 `discovery.json` 的 10 个场景 id。校验脚本同时检查条数、长度、场景合法性与全局唯一性。
- 模型只参与语料撰写；语言模型生成的句子在构建期固化成静态 JSON，`dist/index.html` 内联后运行时不发起任何网络请求，也不需要 WASM / 分词词典。

### 9.2 检索管线（`src/lib/discovery.ts` → `createLongTextSearch`）

1. **归一化**：全角转半角、去标点与空白、小写；中文数字转阿拉伯（十/百/千/万、「两」=2），先保护「一镜到底 / 一键 / 一起」等固定说法；剔除「我想 / 帮我 / 有没有 / 能不能 / 请问 / 麻烦」等语气词。
2. **分词**：不引第三方词典。用 `intents + categories + techStack + tags + 仓库名 + tagline` 构建词表（最长 8 字），正向最长匹配优先；未登录的连续汉字退化为单字 + 2-gram，拉丁/数字按整段保留。
3. **相似度**：`0.45 * 词重合 IDF + 0.35 * 字符 3-gram 余弦 + 0.20 * 短语包含`。词重合权重最高，因为它对「批量 / 竖屏 / 字幕」这类需求词最敏感；3-gram 兜住分词切错与错别字式简写；短语包含保证「把代码讲明白」这类完整说法不被拆散。IDF 用 `log((N+2)/(df+1))+1`，让「视频」这类高频词自动降权。
4. **意图直配**：对每条 intent `q` 用同一套打分取最高，仓库得分 `max(字段分, intent 分 × 1.15)`。1.15 的系数让「用户原话」略优于字段拼词，但不至于压过仓库名精确命中。
5. **长句分段**：去掉停用词后 > 6 字即按逗号 / 句号 / 「然后 / 还要 / 最后 / 另外 / 同时 / 最好」切段；每段独立打分，最终取峰值段 + `0.12 × 其余段平均`。避免 30 字长句被平均稀释，同时不让某个偶然分段独占结果。
6. **场景识别**：场景语料与 `titleZh / questionZh / desc / filters.tags` 打分，按段取峰值；结果前 5 名仓库的 `matchedScenario` 各加 0.04。置信度 `top1/(top1+top2)`，低于 `0.35` 不显示「我理解为」；另设绝对分下限 `0.08`（真实长句实测 ≥ 0.10，无关长句 < 0.08），防止对空话强行归类。若查询属于「免安装 / 少依赖 / 双击出片」类，绝对分下限提高到 `0.15`：这类句子本身不含场景名词，比值置信度没有参考价值。
7. **约束型 rerank（v5.1，文本分之外的结构化信号）**：文本相似度无法区分「同样提到 Windows 出片，但安装成本相反」的项目，因此对约束型查询额外叠加一层结构化打分：
   - **识别**：`install-5min`（不想装 / 免安装 / 双击 / 开箱即用 / 依赖太多）、`has-cli`（命令行 / 终端 / 脚本 / 一键）、`win-workable`（Windows / 本机 / 笔记本）、`official-pipeline`（双击 / 一条命令 / 官方 / 直接出片）、`batchable`（批量 / 自动跑 / 几百条 / 定时）、`no-gpu`（没显卡 / 核显）六类信号，先映射到 `discovery.constraints` 里真实存在的 id；只要命中任意一类即视为约束型查询。
   - **加分**：命中一条已应用约束 `+0.12`，最多累计 2 条（`+0.24`），避免「约束多者通吃」；官方链路且 `installComplexity ≤ 2` 再 `+0.08`。
   - **门槛与扣分**：对「免安装 / 少依赖」类查询，先过轻量门槛（`installComplexity ≤ 2`、Windows 非 broken、非 GPU 必需、官方链路、`cliHeadless === 'yes'`）。过门槛者吃上面的加分；不过门槛者按短板扣分：`installComplexity ≥ 4` `-0.20`、Windows broken `-0.25`、GPU 必需 `-0.20`（可叠加）。
   - **只奖相关项**：加分只给「已命中用户说法」（`matchedPhrase` 非空）的仓库，避免结构化字段完美但与需求无关的项目被抬上来。
   - **权重理由**：0.12 小于一次分段合并的典型差距，能改写同分附近的排序，但不会让文本完全不相关的仓库翻盘；-0.20 ~ -0.25 足以把「需要 Rust 编译 / 必须独显 / Windows 断链」的项目挤出 top3，同时不至于让它们彻底消失（用户仍可在全部项目里找到）。门槛里的 CLI 判定用来区分「可执行工具」与「要写代码调用的库」——双击出片的前提是仓库自带运行入口。
8. **空结果**：`hits` 取 `max(0.15, top1 × 0.4)` 以上的前 12 条；零命中时返回最高分 3 个仓库作为「也许你在找」，推荐说法从**这 3 个近邻的意图原句 + 场景语料 + 全局说法**中按相似度取前 3，且按候选顺序稳定排序，避免退化成固定推荐词。
9. **性能**：首屏一次性建索引（词表、IDF、每条短语的 token set 与 3-gram 向量）。实测 65 仓库 × 910 条意图下，三条真实长句查询耗时 1.4–2.4 ms（测试断言 < 15ms）。

### 9.3 UI 约定

- 关键词搜索框保留原行为（`/` 聚焦、`Esc` 清空、约束 chip 为 AND 叠加）；其下新增 `textarea`「描述你的需求」，占位即真实长句示例。

- 每条长句命中结果标注「匹配到你说的：<intent 原句>」，解释排序来源；关键词结果不显示该行。
